# Tool execution backends: build sidecars and SSH

**Problem.** A slim agent image has no `npm`, `pip`, `mvn`, `go`, `cargo`. **Solution.** Keep
the toolchain in a *sibling* container (or on a remote host) that shares the same workspace,
and put thin wrappers on the agent's `PATH` that forward each command there.

Two backends, one mechanism (`/opt/sidecar/wrappers/*` generated by the image's entrypoint):

| Backend | Config | Transport | Client |
| --- | --- | --- | --- |
| HTTP build sidecar | `tool_backends.sidecars` | HTTP POST to `http://builder-<rt>:<port>` | `/opt/sidecar/sidecar-exec` |
| SSH | `ssh:` block | `ssh user@host 'cd <cwd> && cmd'` | `/opt/sidecar/ssh-exec` |

Sources: `cli/src/runners/sidecar-manager.ts`, `ComposeRunner.buildSidecarOrchestration()`,
`cli/src/templates/sidecar-images.ts`, `cli/build-sidecars/exec-server/main.go`,
`cli/src/templates/assets/{entrypoint.sh,sidecar-exec,ssh-exec}`. Deeper API detail:
**`references/exec-server-api.md`**.

## Quick start

```bash
# 1. build a builder image for the runtime you need
heretic-cli image build-sidecar node             # → heretic-builder-node:latest

# 2. run the agent with that sidecar (one-off)
heretic-cli run claude --sidecar node

# 3. inside the container, npm now works — it runs in the builder, same files
agent@…:/workspace$ npm ci && npm test
```

Persist it in the profile instead of passing flags:

```yaml
volumes:
  - { source: "${CWD}", target: /workspace }   # REQUIRED: builders share this exact bind
tool_backends:
  sidecars:
    - runtime: node
      image: heretic-builder-node:latest
      cache_volumes: ["heretic-npm-cache:/home/builder/.npm"]
  workspace_target: /workspace
  ready_timeout: 60
  run_as_caller_uid: true
```

## The five runtimes and what they capture

`runtime` **must** be one of `node | python | java | go | rust`. Any other key routes
nothing (the entrypoint's wrapper generator only knows these five) and is rejected by
validation.

| runtime | wrapped commands (only those missing from the agent image) | builder base | extra tools |
| --- | --- | --- | --- |
| `node` | `npm npx pnpm yarn node` | `node:<v>-bookworm-slim` (default 22) | corepack (yarn, pnpm) |
| `python` | `python python3 pip pip3 poetry pytest ruff black mypy` | `python:<v>-slim-bookworm` (3.13) | poetry, pytest, ruff, black, mypy |
| `java` | `java javac mvn gradle` | `eclipse-temurin:<v>-jdk` (21) | maven, gradle |
| `go` | `go gofmt` | `golang:<v>-bookworm` (1.23) | — |
| `rust` | `cargo rustc rustfmt clippy` | `rust:<v>-bookworm` (1) | rustfmt, clippy |

A command already present in the agent image is **never** wrapped — the local tool wins.

## CLI flags

```bash
heretic-cli run claude --sidecar node --sidecar python      # replaces the profile's list
heretic-cli run claude --builder-image node=ghcr.io/me/node-builder:2   # retarget a runtime
heretic-cli run claude --disable-sidecars                   # off for this run (wins over --sidecar)
```

- `--sidecar <rt>` defaults each image to `heretic-builder-<rt>:latest`.
- `--builder-image <rt>=<img>` also overrides **profile-declared** sidecars (applied after
  resolution). Malformed value → `--builder-image expects <runtime>=<image>, got '<raw>'`.
- Both flags work in the bare-agent shortcut form (`heretic-cli claude --sidecar node`).
- `runner: custom` cannot orchestrate siblings →
  `Build sidecars require the 'docker' or 'compose' runner, but this profile uses the custom runner.`

## `heretic-cli image build-sidecar <runtime>`

```
heretic-cli image build-sidecar <node|python|java|go|rust>
    -n, --name <name>          default heretic-builder-<runtime>
    -t, --tag <tag>            default latest
    -r, --registry <reg>
        --runtime-version <v>  toolchain version (RUNTIME_VERSION build-arg)
        --go-builder <image>   golang image for the exec-server build stage (default golang:1.23-bookworm)
        --port <port>          port baked into ENV/EXPOSE (default 8080)
    -p, --push                 push after build
        --no-cache
        --dry-run              print the Dockerfile only
    -a, --arch <amd64|arm64|both>
```

Generated Dockerfile is two stages: (1) compile the vendored Go `exec-server` statically
(`CGO_ENABLED=0`, `-trimpath -ldflags="-s -w"`); (2) copy it onto the runtime base, run the
toolchain setup, `useradd -m builder`, set `EXEC_SERVER_RUNTIME/PORT/CWD`, `WORKDIR /workspace`,
`EXPOSE <port>`, a **port-agnostic** `HEALTHCHECK ["exec-server","-healthcheck"]`,
`USER builder`, `CMD ["exec-server"]`.

On success it prints the profile snippet to paste:

```
Use it in a profile:
  tool_backends:
    sidecars:
      - runtime: node
        image: heretic-builder-node:latest
```

You can also **bring your own builder image**: anything that shares the workspace and speaks
the exec-server HTTP contract works. Without a baked `HEALTHCHECK` the docker runner falls
back to an exec probe (`exec-server -healthcheck -port <p>`), so a BYO image should either
declare a healthcheck or ship that binary.

## What orchestration creates (docker runner, dockerode-native)

`SidecarManager` reproduces compose semantics field for field:

1. **Network** `heretic-net-<agent>-<session>-<hash8>` (bridge), labelled
   `heretic.managed=true`, `heretic.role=build-network`, agent/project/session. A 409
   (already exists) is reused, so a crashed prior run doesn't block startup.
2. **One builder per sidecar**, container name
   `heretic-builder-<runtime>-<session>-<hash8>`, network alias `builder-<runtime>`, with:
   - the **same** workspace bind as the agent (`<host source>:<workspace_target>`),
   - `Cmd` = `exec-server -port <p> -cwd <workspace_target>` unless overridden,
   - env: your `env`, `HOME=<workspace_target>/.heretic-home/<runtime>` (when running as the
     caller uid and `HOME` unset), `EXEC_SERVER_PORT=<p>`,
   - `User: <uid>:<gid>` of the calling user (default; `run_as_caller_uid: false` disables),
   - `CapDrop: ["ALL"]`, `SecurityOpt: ["no-new-privileges:true"]`, `RestartPolicy: no`,
     **no published ports**,
   - labels incl. `heretic.role=build-sidecar`, `heretic.runtime`, `heretic.network`,
   - any `cache_volumes` as extra binds.
   A stale container with the same name is force-removed first.
3. **Health gate** — poll `State.Health.Status` (or the exec probe) every 2 s until
   `healthy`, up to `ready_timeout` (default 60 s). A builder that exits early →
   `build sidecar '<name>' exited before becoming healthy (status: …)`; timeout →
   `build sidecar '<name>' did not become healthy within <n>s`. Any failure tears down
   everything created so far and aborts the run.
4. **Agent wiring** — `BUILD_SIDECARS`, `SIDECAR_ENV_PASSTHROUGH` (union across sidecars),
   `NetworkMode` = the shared network (a user-set `extra.network` **wins**, with a warning
   that builders may be unreachable), and label `heretic.network`.

Teardown: in-process on `stop()`; label-driven via `SidecarManager.teardown(docker, {project,
session})` for detached runs; `heretic-cli stop` removes sibling sidecars + the network.
**Named cache volumes are never removed** (warm caches).

## Compose runner parity

`buildSidecarOrchestration()` emits one `builder-<runtime>` service per sidecar with the same
workspace bind, `working_dir`, env, `cap_drop: [ALL]`, `security_opt:
[no-new-privileges:true]`, `restart: "no"`, no ports, `user: <uid>:<gid>`, labels, and a
healthcheck (`["CMD","exec-server","-healthcheck","-port","<p>"]`, interval 2 s, timeout 3 s,
retries `ceil(ready_timeout/2)`, start_period 2 s). The agent service gets
`depends_on: { builder-<rt>: { condition: service_healthy } }`. Named `cache_volumes` are
declared at the top level. Builder services are merged **after** your `compose.services`, so
heretic wins a name collision.

⚠ The compose runner's own `stop()` runs `docker compose down --volumes`, which **deletes**
those cache volumes. `heretic-cli stop` (label-driven) does not.

## The BUILD_SIDECARS contract (normative)

```json
{"node":{"internal_url":"http://builder-node:8080"},
 "python":{"internal_url":"http://builder-python:8080"}}
```

Keys are runtimes (five allowed values only); clients read **only** `internal_url`.
Both runners emit exactly this shape; `sidecar-exec` resolves it with
`jq -r --arg rt "$RUNTIME" '.[$rt].internal_url // empty'`.

## `sidecar-exec` — the agent-side client

`sidecar-exec <runtime> <command> [args…]`, invoked by the generated wrapper.

| Env | Meaning |
| --- | --- |
| `BUILD_SIDECARS` | **required**; the JSON above |
| `SIDECAR_TIMEOUT` | seconds sent to the server (default **600**); curl deadline = timeout + 30 |
| `SIDECAR_CWD` | working dir sent (default `$(pwd)`) |
| `SIDECAR_STREAM` | `1` → use `/exec/stream` (SSE) instead of blocking `/exec` |
| `SIDECAR_ENV_PASSTHROUGH` | comma-separated **allowlist** of env names forwarded per exec |

Exit codes: the command's own code; **124** on timeout (GNU convention); **255** on other
server-side start failures (`exit_code: -1`); **1** on transport/config errors
(`no sidecar available for runtime '<rt>' (available: …)`, `failed to connect to sidecar at
<url>`, `unexpected response from <url>: …`, `stream ended without an exit frame`).

Never forward the whole environment — the agent holds `ANTHROPIC_API_KEY` / `GH_TOKEN`. Use
`env_passthrough` per sidecar (e.g. `["NPM_TOKEN"]`).

Two historical fixes worth knowing, because they explain the odd-looking code: argv is
encoded incrementally with `jq -c --arg x "$_arg" '. + [$x]'` because **jq 1.6 (Debian
bookworm) does not stop option parsing after `--args`** — any dash-flag (`npm install
--save-dev`, `go build -o`) would die with "Unknown option"; and the SSE loop reads from a
process substitution so the real exit code propagates (a pipe's subshell used to swallow it,
making every streamed build exit 0). If routing misbehaves, check `jq --version` in the image.

## The `exec-server` (builder side)

Stdlib-only Go, `version 0.1.0`. Endpoints: `GET /health` (open), `GET /info`,
`POST /exec`, `POST /exec/stream` (SSE). Flags `-port`, `-cwd`, `-healthcheck`; env
`EXEC_SERVER_PORT`, `EXEC_SERVER_CWD`, `EXEC_SERVER_RUNTIME`, `EXEC_SERVER_TOKEN`.
Timeout default 600 s, hard cap 3600 s, request body cap 1 MiB, `ReadHeaderTimeout` 10 s and
**no** read/write timeout (long builds legitimately hold the connection). Commands run with
`Setpgid`, and a timeout kills the whole **process group** so no orphans survive. `/info`
never returns the environment. Set `EXEC_SERVER_TOKEN` to require `Authorization: Bearer …`
on everything except `/health`. Full request/response schemas in
`references/exec-server-api.md`.

## Security posture

- Builders publish **no host ports**; reachable only by network alias on a private network.
- `cap_drop: ALL` + `no-new-privileges` + non-root (`builder` user in the image, or the
  caller's uid at run time).
- `/exec` is **unauthenticated by default** — anyone on that network can run commands in your
  workspace. On a shared host set `EXEC_SERVER_TOKEN` (via the sidecar's `env`) — note the
  bundled `sidecar-exec` does not send a bearer token, so a token currently means you must
  ship your own client.
- Only allowlisted env vars cross into builds.

## SSH backend (alternative)

```yaml
ssh:
  host: build-host.internal
  port: 22
  user: agent
  key_path: /home/you/.ssh/heretic_id_ed25519   # absolute; mounted ro at /home/agent/.ssh/id_rsa
  host_cwd: /home/agent/workspace
```

Sets `SSH_HOST/SSH_PORT/SSH_USER/SSH_KEY_PATH/SSH_HOST_CWD`; the entrypoint then generates
`ssh-exec` wrappers for **every** missing toolchain command (SSH is the catch-all when a
runtime has no sidecar). `ssh-exec` runs
`ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o LogLevel=ERROR -p <port>
[-i key] user@host "cd <cwd> && <escaped argv>"`.

Caveats: host-key checking is **disabled** (trust-on-first-use is off, MITM possible on
untrusted networks); the remote must have the same source tree at `host_cwd` (nothing is
synced for you); combining SSH with sidecars is warned against because one build would span
two filesystems.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| wrappers never appear, `npm: command not found` | image has no baked `ENTRYPOINT` (old image) → rebuild with `heretic-cli image build`, or run with `--root` (which bind-mounts the current entrypoint) |
| `FATAL: /opt/sidecar/wrappers is not writable by agent (uid 1000)` | image built with a different `--agent-uid`, or `extra.user` changed → rebuild with matching uid |
| `sidecar-exec: BUILD_SIDECARS is not set` | wrapper exists but no sidecar wiring — you ran without `--sidecar`/`tool_backends` on an image whose toolchain is missing |
| `no sidecar available for runtime 'x'` | that runtime isn't in `BUILD_SIDECARS` (typo, or `--disable-sidecars`) |
| `tool_backends: no volume targets '/workspace'` | add a volume whose `target` equals `workspace_target` |
| builder unhealthy/timeout | `docker logs heretic-builder-<rt>-<session>-<hash8>`; raise `ready_timeout`; check the image really runs `exec-server` |
| build artifacts owned by root | `run_as_caller_uid` was disabled, or a BYO image forces root |
| every streamed build "succeeds" | you're using an old `sidecar-exec`; regenerate with `heretic-cli image generate --format sidecar-exec` |
| dash-flags fail with `Unknown option` | jq < 1.7 with an old client — same fix |
| builders unreachable | `extra.network` pinned the agent to another network (warning is logged) |
